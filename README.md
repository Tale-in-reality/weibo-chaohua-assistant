# 微博超话助手 · Weibo Chaohua Assistant

给**拍图频的站子**用的本地桌面小工具：懂艺人的话题/事件/梗，写返图文案时自动联想，语气像本人。

**本地优先**——模型跑在本机（Ollama），数据存在本地 SQLite，默认不出网。

> ⚠️ 这是一个**起草工具**，不是内容生成器。成品发出前请自己顺一遍——那是你的语气资产。
> 使用前请先读文末的 [免责声明与合规提示](#-免责声明与合规提示)。

---

## 它解决什么问题

站子写返图文案时，最累的不是「造句」，而是：

- 想不起某个梗/绰号到底什么意思、今年发生过什么
- 每次都要翻聊天记录找以前怎么写的
- 超话刷不过来，怕漏掉重要的事

这个工具把这三件事拆开处理：**风格**来自你的历史文案，**知识**（术语/事件）来自你人工校准的词库，**新消息**来自超话抓取 + 自动速览。

## 功能

| 模块 | 说明 |
|---|---|
| **写文案** | 选模板 → 填对象/氛围/要点 → 本地模型生成，并显示这次联想到了哪些术语/事件/样本。**温度 / 长度两个推子**可调；写要点时按关键词给**词典建议**，点一下就插进去 |
| **文案库** | 你发过的返图文案（风格来源）。支持**逐条删除**；也可**从微博一键导入**：指定「某用户 + 某超话 + 最近多少天」，把它发过的原创帖子抓进来（纯转发/水贴自动跳过，按 mid 去重，重复导入不会重复） |
| **风格档案** | 让模型读完**全部**文案，蒸馏出一份「你的写作规律」说明书（句式 / 标点 / 高频词 / 语气 / 长度 / 禁忌），**每次生成都注入**；加文案后一键重新生成。这是「不改权重也能力求越来越像你」的关键——想真的微调进权重，见 [微调评估](docs/finetune.md) |
| **术语词典** | 圈内梗/绰号的释义（知识核心）；AI 识别的候选词点一下即可确认入库 |
| **词典页** | 全部词条的浏览视图，可就地修改；「有问题的」（AI 建议/低可信/无释义）会高亮 |
| **事件库** | 每条超话帖 = 一条事件（可展开看全文）+ 一条「速览」；**按状态/来源筛选 + 关键词搜索 + 分页**；一键确认/删除待确认；每条可「用它写文案」 |
| **校对台** | 从文案库自动抽可疑词 → 让模型填释义草稿 → 你校准 |
| **超话抓取** | 扫码登录（小号）→ 抓「最新」排序的帖子 → 过滤水贴 → 自动总结 |
| **桌面推送** | 有新速览时弹窗；点弹窗直接跳进 app 的那条速览 |
| **识图写文案**（可选） | 照片 → 云端多模态模型描述画面 → 注入本地写文案的 prompt（默认关闭，照片会出网） |
| **数据维护** | 一键**导出 JSON 备份**（不含设置与登录 cookie）；每天自动清理日志与旧帖（事件/术语/文案不动） |

**应用形态**：双击 `run.bat` 只出一个窗口（`pythonw` 启动，无控制台）；关窗最小化到托盘、定时任务继续跑；点 × 弹「最小化 / 直接退出」选择框（可在设置里固定）。

## 工作原理（核心设计：风格 ≠ 知识）

这是整个项目最重要的一条认知，也是它和「直接问大模型」的区别：

- **文案库只教「怎么写」**（语气/用词/句式），**不含梗义**。
- **术语词典 + 事件库才教「写什么」**——梗指什么、发生过什么事，**必须有人写**。
- 全网大众梗模型可能天生就懂；**圈内黑话/特定事件 100% 要人工喂，没有捷径**。
- 因为**没有微调**，模型不会「记住」任何东西。每次写文案都要把检索到的**释义/事件/风格样本一起注入 prompt**（RAG 思路）。
- 因此「越来越像本人」靠的是**两件事**：① 一份读完全部文案蒸馏出的**风格档案**（规律层面）；② 每次按关键词（BM25 检索、同类型加权）挑出的**风格样本**（实例层面）。二者都在「风格档案」页可调。
- 自动流程只能**提候选**、不能**确认含义**。模型对自己不认识的圈内梗会一本正经地编造，所以校对台会标注「可能编造」——遇到就必须自己写。

> **冷启动建议**：本地 7B 模型从零啃文案很弱。最快的办法是把你一批历史文案交给云端**强模型**（ChatGPT/Claude 等），让它批量产出「术语 → 释义」草稿，你审改后录进术语词典。一天能建好初步词库，之后日常才交给本地模型。

## 环境要求

- **Windows 10/11**（用了 pywebview / pystray / winotify，目前只支持 Windows）
- **Python 3.10+**
- **Ollama**（本地模型运行时）
- 显存 4GB 可跑 7B（会 offload 到内存，稍慢但写短文案够用）；嫌慢可换 3B

## 安装

### 1. 装 Ollama 并准备模型

从 <https://ollama.com/download> 安装，装完启动（托盘出现羊驼图标）。

```bash
ollama pull qwen2.5:7b-instruct     # 或 qwen2.5:3b
```

> **网络受限（如国内）拉不动时**：官方源 `registry.ollama.ai` 可能不可达。
> 可以从 [ModelScope](https://modelscope.cn) 下载单文件 GGUF（如
> `bartowski/Qwen2.5-7B-Instruct-GGUF` 的 `Qwen2.5-7B-Instruct-Q4_K_M.gguf`），
> 放到 `models/` 下，再用仓库里的 `models/Modelfile` 导入：
> ```bash
> ollama create qwen2.5:7b-instruct -f models/Modelfile
> ```
> ⚠️ Ollama **不支持分片（split）GGUF**，务必选单文件版本。

### 2. 装 Python 依赖

```bash
pip install -r requirements.txt
```

### 3. 启动

双击 **`run.bat`**（或命令行 `python -m app.main`）。

- 只出一个应用窗口，没有黑框。
- **重复双击不会开出第二个**：已有的窗口会被唤到前台，第二个实例静默退出。这样避免两个实例抢 8756 端口、导致后端起不来。
  （万一遇到「双击没反应、再双击又说已经在运行」：那多半是个**没有窗口的僵尸进程**占着锁。
  它会在 60 秒内自行退出，稍等再双击即可；急用就去任务管理器结束 `pythonw.exe`。）
- 关窗 ≠ 退出：会最小化到**托盘**，定时任务继续跑；彻底退出在托盘右键菜单。
- 启动没反应时看 `data/app.log`。
- 调试可以只跑服务：`python -m app.main --server-only`，浏览器开 <http://127.0.0.1:8756>。

## 快速开始（建议顺序）

1. **文案库**：把你发过的返图文案放进去（30~100 条最佳）——这是**风格**来源。
   **最快的方式是「从微博导入」**：先扫码登录 → 填用户（昵称/uid/主页链接）+ 超话 + **抓最近多少天** → 一键抓进来，不用手抄。也可以手动批量粘贴。
   导入跑在**后台**：每 20 页休息一下再继续（休息秒数可调，填 0 则不额外休息），一直翻到扫完你设的天数范围；
   期间可以在 app 里做别的事 —— 有**进度条**（已翻到哪天 → 目标哪天）和「停止导入」按钮。
   文案列表按**原帖时间**倒序（最新的在最上面），与导入顺序无关。
2. **术语词典**：手动录入圈内梗/绰号的释义——这是**懂梗**的唯一保证来源。
3. **事件库**：录入和艺人相关的事件（起因/经过/名场面）。
4. **写文案**：选模板 → 填对象/氛围/要点 → 生成。会显示这次联想到了哪些术语、事件、样本。
5. **校对台**：点「抽取候选词」→ 从文案库自动挑出可疑词 → 逐条「让模型填」或自己写释义 → 入库。
6. **设置**：模型名、推送间隔、总结频率、AI 自动识别术语、开机自启、点 × 的行为。

## 超话自动抓取（可选）

> ⚠️ **务必用小号**，并先读 [免责声明](#-免责声明与合规提示)。

1. **推送页 →「扫码登录微博」**：用微博 App 扫码（**小号**），登录成功后 cookie 自动写入。
2. **按超话名称找 containerid**：输入名称，从候选里点「用它」。
   （也可手动：超话主页 → F12 → Network → 找 `getIndex?containerid=...`，复制完整值。）
3. **推送页 →「抓取超话新帖」**：抓到新帖会**自动总结**——
   - **每条帖子 = 一条事件**，点标题展开看**完整原文**，待确认；
   - **另生成一条「速览」**，把整批内容压成几条要点；**桌面推送推的就是这条**，点弹窗跳到 app 里的速览。

**抓取规则**：

- 只取**「最新」排序**（containerid 加 `_-_sort_time`）里的帖子，保证按时间。
- 抓取窗口 = 距上次成功抓取的时间（至少一个抓取间隔），把窗口内的帖子全抓下来。
- **水贴过滤**：只发几个字、纯表情、或**只有转发链没有本人内容**的帖子直接忽略，不进库也不喂给模型。
- 有**页数上限**（防封号的安全阀）：热门超话一小时可能上千页，到顶会提示「有截断」。

**风控**：遇风控（HTTP 403/418/432）会**自动停下并弹窗告知**，绝不硬重试。但风控无法 100% 避免——用小号、别把间隔设太小。

**请求节流**（`app/modules/pacing.py`）：所有对微博的请求都先过 `pacing.pace()` ——
**两请求之间强制留 1.0~2.5 秒的随机间隔**，既保证不背靠背连发（「按名找超话」一次查 3 类、
导入长文连发取全文都属于连发），也让节奏不固定。觉得太慢/太快改这两个常量即可：

```python
MIN_GAP = 1.0        # 最小间隔（秒）
JITTER = 1.5         # 再叠加 0~JITTER 的随机量
```

⚠️ **别把间隔改成固定值** —— 固定节律本身就是机器特征。

## 项目结构

```
app/
  main.py        入口：uvicorn 服务 + pystray 托盘 + pywebview 窗口
  api.py         FastAPI 路由
  db.py          SQLite 建表 + 数据访问
  llm.py         Ollama 调用封装
  scheduler.py   APScheduler 定时任务（抓取 / 推送 / 总结）
  notify.py      Windows 桌面弹窗（winotify）+ 点击跳回 app 的协议注册
  winref.py      运行中的窗口引用（唤起窗口 / 跳页）
  toast_click.py 弹窗点击的回调入口（独立进程，只用标准库）
  autostart.py   开机自启
  modules/
    captions.py    写文案：检索 + 注入 prompt
    terms.py       术语词典 + 候选抽取
    events.py      事件库
    summarize.py   帖子 → 事件 + 速览
    fetcher.py     超话抓取（最新排序 / 时间窗 / 水贴过滤）
    weibo_login.py 扫码登录、按名找超话、登录态检查
    vision.py      识图（可选，云端 VLM）
    style.py       风格档案（读完全部文案 → 蒸馏成说明书）
    housekeeping.py 数据清理（日志截断 / 旧帖回收）
  util.py        公共工具（JSON 抠取 / jieba 分词 / BM25 检索）
docs/            finetune.md（要不要微调、要多少数据、云训练多少钱）
web/             index.html / app.js / style.css（无框架，原生 JS）
tests/           pytest 用例（纯函数 + 数据层，用临时库，不碰真实数据）
data/            运行后生成：fan.db（文案/术语/事件/设置/cookie）
models/          Modelfile（导入 GGUF 用）
```

`data/` **不入版本库**——里面存着你的微博 cookie 和各库内容，请勿外传。

## 开发与测试

```bash
pip install -r requirements-dev.txt   # 测试依赖（跑 app 还需 requirements.txt）
pytest -q                             # 34 个用例：水贴过滤 / 时间解析 / 分页筛选 / JSON 解析 / BM25 检索 / 风格注入
python -m compileall -q app           # 语法检查
```

推送/PR 会由 GitHub Actions（`.github/workflows/ci.yml`）在 Windows + Python 3.10/3.12 上自动跑上面两步。

**安全设计**：本地 API 对所有改动类请求要求带 `X-Requested-With` 头——第三方网页无法自定义该头（会被 CORS 预检拦住），因此能挡掉「恶意网页偷调本机接口」的 CSRF。
