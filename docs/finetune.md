# 微调评估：想让模型「越来越像你」，值得吗？

这份文档回答一个问题：**要不要把文案微调进模型权重（LoRA），而不是每次注入风格档案 + 样本？**

结论先给：**大多数情况不值得**。先用「风格档案」；等文案攒到 500 条以上、且觉得还不够像，再考虑上云训一次。

---

## 1. 为什么本地训不动

「推理能跑」≠「训练能跑」。两者的显存占用不是一个量级：

| | 显存里要同时装什么 |
|---|---|
| **推理**（写文案） | 只有**权重**。7B 4-bit ≈ 4GB；装不下可以逐层从内存流进来 —— 慢，但**能跑** |
| **训练**（LoRA） | 权重 **+ 梯度 + 优化器状态**（AdamW 每个可训练参数要存 2 个动量）**+ 激活值**（随 batch×序列长度增长） |

**训练没法像推理那样优雅 offload**：每一步要做 前向 → 反向 → 更新，中间状态必须同时活着。

现实最低显存（QLoRA，4-bit 基座）：

| 模型 | 训练最低显存 | 你这台（4GB） |
|---|---|---|
| 7B | ≈ 8~10 GB（unsloth 极致优化约 8GB） | ❌ |
| 3B | ≈ 5~6 GB | ❌ |
| 1.5B | ≈ 3~4 GB | ⚠️ 勉强，但写中文文案太弱 |
| 0.5B | ≈ 2~3 GB | ✅ 装得下，但能力不够，没意义 |

硬上 4GB 的结果：**OOM 崩掉**，或退化到内存里算 → **慢 10~50 倍**（几十分钟变几天）。

> 「后台静默跑」也救不了：**同一块 GPU**，训练占着它，前台写文案就会慢到没法用。

---

## 2. 唯一现实的路：租云 GPU

「让它在后台静静地训」—— 把这个「后台」放到云上就成立了：

1. 在云上训练（占云卡，不占你机器）
2. 导出一个 **50~200MB 的 LoRA adapter**
3. 拉回本地，导入 Ollama 变成一个新模型
4. 你的机器**只做推理**（本来就跑得动）

**参考成本**（2026 年前后行情，仅供估算）：

| 平台 | 卡 | 价格 | 训一个 LoRA |
|---|---|---|---|
| AutoDL / 恒源云（国内） | RTX 3090 24G | ≈ ¥1~2/小时 | 500~2000 条数据约 20~60 分钟 → **几块钱** |
| RunPod / Vast.ai（国外） | RTX 4090 | ≈ $0.3~0.6/小时 | 同上 |

**工具链**（Ollama **不训练**，要另找）：
- [unsloth](https://github.com/unslothai/unsloth) —— 最省显存、最快，笔记本教程最全
- [LLaMA-Factory](https://github.com/hiyouga/LLaMA-Factory) —— 有 WebUI，不写代码也能跑
- axolotl / peft + transformers —— 更底层

训练完导出为 GGUF（或 adapter + 合并）后：

```bash
# 用仓库里的 Modelfile 思路导入
ollama create my-style -f Modelfile
# 然后在「设置」里把模型名改成 my-style
```

## 3. 数据量：这是最容易被低估的一点

| 文案条数 | 训练结果 |
|---|---|
| 60~100 | **严重过拟合** —— 模型开始**原样照抄**你写过的句子，而不会写新的 |
| 300~500 | 开始有像样的风格迁移，但仍易过拟合 |
| **500~2000** | **推荐区间** —— 风格稳定，且能写新内容 |
| > 5000 | 收益递减 |

**而且微调不是「持续训练」**：

- ❌ 不能在上一版 adapter 上接着训 —— 会**灾难性遗忘**（学新的、忘旧的）
- ✅ 它是**批处理**：攒一批文案 → 从基座重训 → 换上新模型

所以流程是「每攒够几百条，重训一次」，不是后台一直跑。

---

## 4. 微调 vs 风格档案：到底差在哪

| | 风格档案（本仓库已实现） | LoRA 微调 |
|---|---|---|
| 是否改动权重 | ❌ 不改 | ✅ 改 |
| 能「读完全部文案」吗 | ✅ 能（蒸馏成说明书） | ✅ 能（但受数据量限制） |
| 加新文案后 | 点一下「重新生成」，**立刻生效** | 要**重新训一轮** |
| 可控性 | 高 —— 说明书可手改、可加禁忌 | 低 —— 训歪了只能重训 |
| 成本 | 0 | 几块钱 + 每次重训的时间 |
| 适合 | 文案 < 500 条 | 文案 ≥ 500 条且追求极致 |

**关键认知**：风格档案已经把「读完你所有文案」这件事做到了。LoRA 的额外收益主要在**少注入上下文**（快一点）和**更细的语气粒度**，而不是「从不像变成像」。

---

## 5. 建议路线

1. **现在**：录 60~100 条文案 → 生成**风格档案** → 把注入样本提到 8~12 条 → 用起来
2. **攒到 300+ 条**：重新生成档案，看看是否已经够像
3. **攒到 500+ 条且仍不满意**：租云卡训一次 LoRA（几块钱），和「档案版」**盲测对比**再决定用哪个
4. **持续**：每攒 300~500 条，重训一次

## 附：真正的「向量检索」

本仓库现在的检索是 **BM25**（`app/util.py` 的 `bm25_rank`）—— 纯 Python、零依赖、完全本地，对短文本已经比字符重叠准得多。

想要神经向量（embedding）检索的话，需要额外准备一个 embedding 模型：

- **本地方案**：从 [ModelScope](https://modelscope.cn) 下载 BGE / M3E 之类的中文 embedding 模型（和下载 GGUF 一个思路，`registry.ollama.ai` 在国内可能不通），配 `sentence-transformers` 使用
- **云方案**：很多 OpenAI 兼容中转站都提供 `/v1/embeddings` —— 但那意味着**文案会出网**，与「本地优先」冲突，默认不建议

对当前这个规模（几百到几千条短文案），BM25 通常已经够用；数据量再大或者语义检索需求明显时再上向量。
